1. Check the exact target repository, permissions, `main` SHA/tree, open/draft PRs, checks and dirty local work. Treat branch/PR metadata as current work state; do not create a parallel mutable task-state service.

A safely parked external/activation hold does not stop independent work. Own exactly one bounded operator journey; do not add a coordinator.
4. Do not mistake a previous model message, uploaded Git object, fixture PASS, or an unmerged PR for current authoritative source.

## 2. Define the smallest end-to-end outcome

Use a short working note, **not another approval artifact**: operator action/result, relevant AC/T/E, first failing boundary, affected interfaces, preserved invariants, existing evidence, independent oracle, rollback and real hold. Follow ingress → durable state → guarded effect → independent observation → dashboard. Consider affected consumers without reopening settled design without measured contrary evidence.

The accepted client contract and prescriptive security requirements cannot be weakened. Standing slice implementation authority covers compatible cross-module fixes, internal mechanism replacement and technical choices without a product vote. Product/security guarantee changes, protected routing/external-effect authority, CI trust roots and irreversible operations outside standing authorization require genuinely narrow approval. **Failed** E-01/E-04/E-06/E-08 gates block dependent unsafe work and demand repair/amendment; **unavailable** external proof holds its effect, not safely dormant independent code.

## 3. Work and prove

1. Reproduce actual defects at their smallest boundary and establish a meaningful failing adverse test where practical. Do not require synthetic proof exercises for purely hypothetical defects.
2. Make the smallest compatible correction. Keep durable intent and possible-effect records before remote dispatch. For any ambiguous ACK, persist an uncertain state and perform read-only reconciliation before another write.
3. Test affected positive, negative, supersession and recovery behavior at available relevant D/B/H/GIT/L tiers using production entrypoints. Preserve independent effect ledgers; label simulated evidence. Reuse unchanged valid proof and run all current required CI/affected regressions rather than ceremonial historical re-runs.
4. Use an **actually installed, enabled** packaged XPI for B claims. A temporary add-on or tab reload cannot prove cold process restart. Real L, GIT, host installation or operator-profile effects require their own exact authorization and safe disposable scope.
5. Preserve frozen donor and Stage 7 originals. Never mutate the original I17 uncertain CREATE/RENAME. An absent original Firefox journal blocks only affected original-profile reconciliation and shared-resource cutovers; verified-empty detached disposable profiles can be developed independently.

## 4. Durable GitHub progress and review

Create/resume a purpose-named branch and early draft PR after authorization and initial examination. Push redacted, coherent checkpoints (no secrets or profile material); verify **remote branch HEAD and tree** after each meaningful checkpoint. Ref update failure => re-fetch/reconcile, never force. Keep runtime generator-source Git effects separate from implementation repo changes. Never merge a source-authoring branch merely because a PCMS runtime operation would be allowed to write its tested result to `per-gens/main`.

Protected instructions, CI selector/required checks, security/acceptance mapping and workflow privileges require the **actual final diff** to be reviewed by the operator or genuinely independent trusted authority, under existing protection. The author cannot self-certify, bypass or fabricate approval. This exceptional review is not required for every ordinary code/interface/test refactor. Other complete, safely verified work may be squash-merged by a delegated actor after real required CI and branch/rule/thread checks, without repeated architecture votes. Verify postmerge `main` HEAD/tree and CI.

## 5. When blocked; completion report

On unavailable L/H/GIT access, record missing tier and keep its dependent runtime operation dormant; finish and, if protected governance permits, merge independent safe implementation. On failed required CI, installed-Firefox evidence, actual correctness or unsafe behavior, fix first causal defect before affected merge. Do not block solely for hypothetical scale, speculative architecture, unrelated inaccessible environment or additional optional review. Measure real performance; maintain intended 50+/1,000+ scale with safe bounded resource limits.

Every handoff/PR checkpoint states:

- Slice ID, journey, AC/T/E and distinguish **implementation incomplete**, **verified at available tiers**, **merged safely dormant pending external evidence**, **full live/product acceptance**, or **actual failure**; report D/B/H/GIT/L individually. This is reporting language, not a new status registry.
- Exact branch, PR, remotely verified commit/tree, package/donor/host/browser versions and XPI digest where applicable.
- Changed paths and compatible cross-cutting fixes; commands run, independent observations, negative tests, substitutions and first unresolved failure.
- Scope of authorized effects, possible remote effects, rollback/quarantine, unmet proof or operator authority, and one precise next step.

Do not claim full AC/live completion while essential native, Git or provider proof is missing. Finish all safe work through permitted merge and postmerge verification, or leave a complete durable PR and one precise genuine hold; stop after this one slice.
