# I17 source-save Refresher amendment — 2026-10-15

Authority: the operator's attached `PCMS-I17-Refresher-Agent-Prompt.md`,
`TODO.md`, and explicit instruction to implement them on existing draft PR #20.
This is a later, additive product decision. It does not re-sign Stage 7.

For an owned, verified, publicly listed generator, **refresh** means one native
Perchance Save of an explicitly consented, behavior-preserving PCMS source
marker, followed by independent complete saved-source and recent-list reads.
The stable method is `GUARDED_SOURCE_SAVE`, policy version `html_prefix_v1`.
No special refresh endpoint is required.

Only for this operation, this decision supersedes Stage 2 §5.1's prohibition
on modifying code as a shortcut, Stage 2 §5.6 / Stage 5 P54-05's exclusion of
comment-only changes, and the implementation's `EXPLICIT_PROVIDER_REFRESH`
restriction. The I17 authorization's permissible-method requirement includes
this native source save. Permissibility and effectiveness still require
evidence appropriate to the actual target, method version and repeated use.
This grants implementation and an explicitly armed single-target operator
test; it does not establish H-04 acceptance or unlimited recurring efficacy.

## Exact source authority

The reviewed/tested/released functional source F and Git `per-gens` remain
authoritative. Consent pins F, owner binding, target, policy and one reviewed
HTML prefix slot. A marker is a non-executable comment at byte zero, before
any original HTML (optionally before a doctype). No substring search through
scripts, styles, templates or strings is permitted. A source already using
PCMS marker syntax anywhere else is ambiguous and held. Initialization is
shown as an exact diff and requires a separate exact-source consent. No
arbitrary anchor creation or hidden functional-source approval is granted.

Every derivation pins the exact pre/post full-manifest hashes, base F,
monotonic marker sequence, operation ID, consent revision and independently
verified effective current fingerprint. Replacement changes only that one
prefix comment; PJS/assets and all remaining HTML must match byte for byte.
An immutable provenance receipt identifies `PCMS_REFRESH_MARKER`, before,
after and observation time. Unknown source changes remain hard holds.
Other workflows may recognize only an exact verified derivation, or require
explicit source reconciliation. They must never ignore source differences
globally, rewrite Git automatically or replace previous-good P with unreviewed
source. Historical/restored receipts confer no fresh execution authority.

## Preserved safety and rollout

One donor Persona control/lease boundary, verified owner/account, protected
route without Direct fallback, human/dirty/collaborative editor protection,
exact source approval, durable journal before effect, independent persisted
bytes, separate feed presence/rank, no blind retries, scoped Pauses, active
24h / minimum sleep 72h defaults, rate/backpressure limits, one coalesced
scheduler, P54-09 / P56 resource proof and release/CI review remain required.

An absent feed snapshot is not evidence of deletion, private status or banning.
ACK is not source confirmation; source confirmation is not rank. An uncertain
save permits only bounded readback. Ineffectiveness, refusal or repetitive
change filtering suspends affected mutation; no alternate marker tricks.
Recurring use requires independently reviewed operator evidence and measured
resource safeguards plus explicit scoped opt-in, using the same installed XPI.
Coding agents and CI use isolated fixtures only; authenticated live H evidence
belongs to the operator/local agent. Keep PR #20 draft and unmerged pending
the existing independent governance and live acceptance requirements.

Frozen signed originals and their checksums, historical authorizations,
accepted I00–I16 records, CI required jobs/privileges and H gates are unchanged.
