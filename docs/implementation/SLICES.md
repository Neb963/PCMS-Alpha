Failed required CI/unsafe effects block affected merge; absent unrelated access does not.
### Selection and truthful promotion

- Under **“Implement the next eligible authorized slice”**, resume relevant unfinished/postmerge-unverified work, otherwise select the first engineering-eligible slice independently. Historical I17 PR #20 is not automatically inherited. S03 pinned-`main` catalog/prompt engineering can follow merged S00/S02 without waiting for S02 deferred production-v2 release or unrelated live-provider acceptance.
- One agent implements exactly one slice per invocation with necessary compatible cross-cutting fixes. A parked external/activation hold does not immobilize independent code; speculative redesign or extra reviews need actual evidence/authority.
- Verified code may merge safely dormant with missing external proof explicitly recorded, but cannot be called live accepted. Required D/B failures must be fixed; all actual applicable negative/recovery tests retain their correct evidence tiers.
- Retain early S01 E-01/E-04, S02 E-06 format and E-08 restart viability gates before dependent **risky** implementation/activation. Address demonstrated failure before its dependent work; do not impose unrelated external proof on S03.
- This map contains no manually maintained status fields. Read actual state from remote PR/merge/evidence artifacts. Any plan change that alters accepted behavior or weakens a proof boundary requires targeted approval and a logged supersession, not an invisible checklist edit.
