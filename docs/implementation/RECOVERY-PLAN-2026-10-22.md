3. The 61 numbered Part 2–7 observations overlap; the 15 synthesis domains are repair ownership groups, **not** 15 independent proven runtime crashes. Preserve CONFIRMED / REPRODUCED / DERIVED / UNVERIFIED labels on each narrower finding.
4. **New cross-boundary finding — credential isolation.** Firefox exposes `storage.local` to extension content scripts by default; `StorageArea.setAccessLevel()` is not supported by Firefox per MDN compatibility data inspected 2026-10-22. Therefore the approved browser-local, passwordless Git token must use a **background-owned, extension-origin durable IndexedDB store or another proved equally restricted Firefox-native store**, not an unqualified `storage.local` secret key. Verify access denial from real installed content scripts and UI messages; do not expose the token in logs, XPI, exports, page responses or fixtures. An extension-compromised trusted background is outside this boundary.
5. Browser alarms are wake hints, **not** persistent operating-time evidence. Rest accrues valid wall time across closure, active qualified operating time cannot be fabricated, and every possibly dispatched effect requires read-only reconciliation before another write.
6. The R4 native installer and old UI tests must be replaced **as the corresponding features migrate**, not simply removed first. Never ship an intermediate broken XPI or mark a simulated gate as provider acceptance.
7. A Firefox-only archive can verify its own bytes before download and verify a later imported file. The Downloads API alone cannot certify that the exact bytes were durably reopened from disk. Do not call DOWNLOAD_COMPLETED equivalent to independent disk-readback H.
8. Current real profiles, existing native host registrations, actual private Git rules, latest Perchance adapters, unsigned Firefox version/permission behavior, source-heavy memory and real Mullvad exits remain **unknown until specifically observed**. Do not infer safe migration or successful live operation from code.
