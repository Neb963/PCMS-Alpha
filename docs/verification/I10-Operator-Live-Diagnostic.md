# I10 — Operator-controlled native AI diagnostic (disposable generator)

**Status:** separate H/live diagnostic preparation, not F/B completion or provider activation. The diagnostic does not authorize PCMS to execute AI tasks. It does not establish an independent Perchance server-history or worker-init acceptance oracle.

## Authority and privacy

Use a disposable, operator-owned, unlisted Perchance generator in a disposable Persona. The site's internal `isPrivate` and `userOwnsThisGenerator` globals are not reliable prerequisites for a **read-only** standalone diagnostic; absence of those flags is reported, not accepted as a PCMS execution authorization. PCMS's own guarded native-effect ownership requirements remain unchanged. The operator must already be logged in directly in Firefox. **No account credentials, tokens, cookies, session IDs, raw URL queries, complete transcripts or generator source code belong in this public repository, Actions, a PR comment, or the diagnostic export.** Do not alter Mullvad, Cloudflare, PersonaMonkey routing or any protected-user state for this test. Do not use production generators.

A standalone user-installed diagnostic uses an existing editor tab and native controls; it must not send AI prompts, bypass the native New Chat confirmation, create/edit/save generators, or make provider requests. The operator may manually use normal Perchance controls on the disposable generator when ready. Diagnostic network observations, if available, are restricted to endpoint class and elapsed milliseconds; never collect request or response bodies, full URLs or response headers.

**Script distribution:** `PCMS-I10-Live-Diagnostics-v0.2.0.user.txt` is an operator-side conversational attachment (version `0.2.0`, SHA-256 `2802d1f8a05441f974c936d708237b8e2e37a8cbcbe16f9d5893b217bf48aefc`). It is supplied as `.txt` for manual paste into the user's userscript manager, **not** committed as an executable repository userscript or injected into the XPI. The repository contains only this non-secret instructions/checkpoint. The script itself must be verified against the stated digest before use.

## Bounded operator protocol

1. Open exactly `https://perchance.org/<disposable-slug>#edit` in a logged-in Firefox editor, verify private, unlisted ownership and clean/absence of human unsaved edits. Replace/disable v0.1.0 in Violentmonkey and enable **v0.2.0** on this page. Reload. Click **Snapshot / adapter check** first: the panel must provide an immediate success message or a specific visible failure. It must also show the native SID adapter, native control presence, and site owner/visibility flags without allowing a missing private flag to block passive diagnostics. The panel must say *local diagnostics*, not a server PASS.
2. Run the existing native AI helper manually for a small reversible Chat 1 change. After it is idle/saved, press **Capture Chat 1**. If it is still busy, v0.2.0 records S1 but explicitly warns not to reset until idle; if the session accessor is absent or the native UI is missing, the panel must display a specific error immediately rather than silently doing nothing. Record a salted hash of S1, local message count, save/dirty state and optional salted PJS/HTML panel-only checksums (not a complete generator F); never disclose S1.
3. Manually press the native **New Chat** button and accept its own confirmation. Press **Check reset**. If it is premature, the control remains clickable and displays which prerequisite has not been met. Expect an empty native input/queue/attachments, no active S1 and at most the known static greeting. This is merely **local** reset evidence.
4. Manually send one safe, short Chat 2 prompt using the native helper (not the diagnostics). Once the new session has actually been allocated and is idle, press **Capture Chat 2**. The script checks S2 differs from S1, and read-only OPFS `attachments/<sid>` and `agent/<sid>/workspace` directory presence. It reports directory presence as **untrusted**.
5. Stop sampling, export **redacted JSON**, inspect before sharing. Ensure the export contains no slug, credentials, full URLs, messages, source code or raw SIDs. The report intentionally keeps server history, worker isolation, full-source fingerprint and independent tests **UNVERIFIED**; it is not sufficient by itself to mark `FRESH_VERIFIED`.
6. Separately use the PCMS extension's independent source/test observations for any candidate F. If the remote/history/worker question remains ambiguous, keep the I10 Chat 2 gate held and record the smallest redacted failure, rather than retrying or publishing.

## Interpretation / failure cases

A new session hash, UI reset, OPFS directory or network timing observation **cannot** prove that the new server conversation contains no old S1 history or that the active native tools worker uses only S2's workspace. Neither the script nor the existing XPI can replace the independent P52-06 F/B verification adapter. If the browser privacy/ownership guard is false, if the source is dirty, or if the native New Chat dialog is canceled, stop without sending. Keep AI provider automation, Git writeback, and publication disabled.

**Next engineering action:** connect a trusted read-only native history/worker observation to the canonical source- and revision-fenced `FRESH_VERIFIED` state transition, and prove positive and negative cases in independent F and packaged B before implementation acceptance. The live diagnostic is useful to diagnose an actual helper revision, not an alternative source of false PASS.

## 2026-10-13 v0.1.0 live regression and v0.2.0 fix

The operator supplied two **redacted v0.1.0** reports showing repeated `PRIVATE_OWNED_EDITOR_NOT_VERIFIED` on Chat 1 and Snapshot, with zero successful snapshots. The old script equated `app.data.generator.isPrivate===true`, `window.userOwnsThisGenerator===true`, and `window.__editorReady===true` with permission to **read passive diagnostics**, even though the visible generator was unlisted and the site does not guarantee those globals. Worse, the old UI recorded HOLD events in the export but did not display failure feedback: Capture appeared inert. The prior single synthetic test only provided all matching globals and missed this real failure.

**v0.2.0 changes (separate operator-side artifact, not an XPI patch):** passive local diagnostics do not gate on undocumented flags; the snapshot reports flags as unverified hints. All step buttons are operable until a read is in progress or monitoring is explicitly stopped. Every rejection includes a prominent accessible panel message with the reason and next action. A Snapshot returns adapter details even when the site SID interface is unavailable; Chat 1/S2 identity still requires an actual SID accessor, and no tests or workspace isolation are ever claimed from local flags. Redaction, native helper ownership of all Send/New Chat actions, no credential collection, and no fetch/remote mutation remain enforced.

**Executed local synthetic v0.2.0 test harness (not F/B acceptance):** 12/12 explicit positive/negative scenarios: old overlay cleanup; unlisted editor with undefined owner/ready flags; Snapshot with unknown flags; missing SID accessor; incomplete native UI; wrong order Step 2/3; busy Chat 1; successful S1→reset→S2; reused SID held; no raw SID/slug/source in JSON; Stop/Close; and auto-sampling with zero outbound fetch calls. JS syntax check passed. Real Firefox/provider capture after this replacement remains operator-run and **not yet claimed**. Future diagnostic versions must test unsupported site flags and visible error feedback, not only an ideal private/owner fixture.

**Final v0.2.0 browser smoke:** A locally served/synthetic Chromium Shadow DOM flow exercised wrong-order buttons, an unlisted generator with absent ownership flags, visible adapter Snapshot, S1 capture, local reset, distinct S2, and exported redacted JSON. There were **zero Perchance/provider network requests**. The earlier Node test matrix was rerun after fixing automatic sample feedback: the five-second background sampler no longer replaces a manual warning or successful action with an indefinite `SAMPLE: inspecting` message. These are local UI regression tests, not Firefox/Perchance live acceptance.
