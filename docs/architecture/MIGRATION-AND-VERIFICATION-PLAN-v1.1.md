## 4. Rollback without fictional external undo

1. Stop new admission, persist outer hold, preserve all claims and operation journals. Observe potentially dispatched effects before selecting rollback steps. Closing UI or disabling a feature does not prove remote AI stopped.
2. If only additive metadata was written, compatible old readers may inspect retained legacy records. **Do not run an old mutator** on newer state, new path associations, admitted donor gates or new source format. Rollback defaults to safe read-only/held mode until a compatibility check explicitly permits execution.
3. Restore local schema from the verified checkpoint only after preserving newer journals/source/exclusions and presenting the restore plan. Restoring old local state cannot erase newer possible remote effects, historical reservations or removal facts. The independent outer gate survives database replacement.
4. Donor/host downgrade never silently removes the managed-traffic gate. Block managed Personas before downgrade and keep durable gate metadata; if old donor cannot enforce it, do not activate that combination. Ordinary protected donor capability remains available where independently safe. Never use Direct for rollback.
5. Provider source rollback uses a proven previous-good manifest, current owner/route/editor checks and a new journaled save. Independently verify it and keep it unlisted. Public re-listing requires applicable human authority; no timer or failed update grants it. Unknown unlist/publish continues consuming the public-update hold.
6. Git rollback is never force-push/history rewrite. Preserve actual commit/ref outcome; a later explicitly scoped compensating commit needs current relevant-path checks and exact readback. Do not rewrite external source edits or delete archival refs to make history look unchanged.
7. Backup v1 import remains supported; v2 is explicitly versioned and unsupported old software refuses it. Keep known-good artifacts until actual restored source/Persona mappings/activation are proved. A failed new archive does not consume retention or delete old good data. Manual exports are outside automatic cleanup.

There is no globally atomic rollback across IndexedDB, donor storage, Firefox identities/cookies, Perchance and GitHub. Per-scope recorded phases, fail-closed startup and observational recovery are the mechanism.
